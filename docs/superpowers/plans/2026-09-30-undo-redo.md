# Undo and Redo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `undo` reverses the last command typed and `redo` puts it back, for any command, on the CLI and the chat page, for the length of a session.

**Architecture:** An `UndoJournal` in the engine keeps a shadow copy of the workspace. Around each command it scans file stamps before and after, and keeps only the changed files' before and after versions (on disk), plus the in-memory session state and the project registry. Undo and redo write those versions back after checking that nothing was edited outside the tool since. The CLI loop and `ChatSession` each own a journal and route the new `CommandKind.Undo`/`Redo` to it. The chat composer gets two buttons that send the words.

**Tech Stack:** .NET 10, C#, MSTest (`CodeGenerator.Tests`), bUnit.

**Spec:** `docs/superpowers/specs/2026-09-30-undo-redo-design.md`

## Global Constraints

- Session only. Nothing about the history is persisted; the shadow folder is deleted on `Dispose`.
- One entry per typed command. The history holds at most **50** entries; the oldest drop off.
- A new entry clears the redo list.
- A command that changes no file and no state makes **no** entry.
- Excluded from the shadow, and so never rolled back: `bin obj .git TestResults node_modules .codegen .dd-cache`.
- Size guard: over **5,000 files or 200 MB** the journal switches off for the session and says so once. It never prompts.
- Messages, exactly:
  - `Undid: <label> — restored <file>` (one file), or `— restored N files, removed M` (counts, a part omitted when 0);
  - `Redid: <label> — …` in the same format;
  - `Nothing to undo.` / `Nothing to redo.`
  - `Can't undo: <file> has changed since <label>.` / `Can't redo: <file> has changed since you undid <label>.`
  - A state-only entry has no "—" part: `Undid: use project Shop`.
- Not journalled: `undo`, `redo`, `exit`, `clear`, `history`, `help`, `status`, `ai`, `chat`, and single-shot `RunOnce`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Write messages to a file and use `git commit -F`.
- Python edits read and write bytes and keep the file's line endings and BOM. Never use `sed -i` on CRLF files.

## Review Focus

1. **An edit you made in Visual Studio between two commands** must not be undone by the next undo, and must not be folded into the next command's entry. Tests are in Task 2.
2. **Undo after you edited the very file** it would restore must refuse and name the file, leaving everything as it is. Tests are in Task 2.
3. **Undo of `build app`/`create project`**, which added whole folders, must remove the files **and** the now-empty folders it created. Tests are in Task 2 and the live run in Task 6.
4. **A nested command** (a `batch` or `demo` running commands through the same loop) is still one entry. Tests are in Task 2.
5. **The chat page switching workspace** (`Load`) must not let an undo write into the old folder. Tests are in Task 5.

        string? registryPath = null, Func<ISessionState>? captureState = null, string? shadowParent = null);
    public string WorkspaceRoot { get; }
    public bool Enabled { get; }
    public bool CanUndo { get; }
    public bool CanRedo { get; }
    public string? NextUndoLabel { get; }
    public string? NextRedoLabel { get; }
    public IDisposable Begin(string label);   // a no-op scope when disabled or already inside one
    public UndoResult Undo();
    public UndoResult Redo();
    public void Dispose();
}
public interface ISessionState { bool SameAs(ISessionState other); void Restore(); }

- [ ] **Step 3: Implement** `UndoJournal`. Its shape:
  - `_known : Dictionary<string, (long Length, DateTime WriteUtc)>`, keyed by relative path (OrdinalIgnoreCase). It is the workspace as the shadow holds it.
  - Shadow layout: `<shadowParent>/codegen_undo_<random>/files/<rel>` holds the current copy; `.../entries/<n>/before/<rel>` and `.../entries/<n>/after/<rel>` hold one entry's versions.
  - **First `Begin`:** `Measure`, using `IncludedFiles(root, [".codegen", ".dd-cache"])`. Over the limits: `Enabled = false`; `notify?.Invoke("Undo is off for this session: the workspace has more than 5,000 files or 200 MB.")`; return a no-op scope. Otherwise copy every included file to `files/` and fill `_known`.
  - **`Begin(label)`** when a scope is already open: return a no-op scope, so the depth counter nests. Otherwise:
    1. `Sync()`: scan; for each path whose stamp differs from `_known` or is missing from it, copy it into `files/`; for each path in `_known` no longer on disk, delete it from `files/`. Update `_known`. This makes no entry.
    2. Capture state (Task 3; null here) and the registry bytes (Task 3).
    3. Return a scope whose `Dispose` calls `End(label)`.
  - **`End(label)`:** scan. `changed` = new, modified or deleted relative paths versus `_known`. For each, copy `files/<rel>` (if present) to `entries/n/before/<rel>` and the workspace file (if present) to `entries/n/after/<rel>`, then update `files/` and `_known`. Also record the **directories** that exist now but did not exist at `Begin` (collected by listing directories under root before and after, excluding none). Undo deletes those trees whole, which removes created `bin`/`obj`. If `changed` is empty and the state is unchanged, delete `entries/n` and push nothing. Otherwise push the entry, clear redo, and drop the oldest past `Capacity` (deleting its folder).
  - **`Undo()`:**
    1. No entry: `Nothing to undo.` Disabled: the off message.
    2. For every changed path, compare the current workspace bytes with `after/` (a missing file matches a missing after). On the first difference, return `Can't undo: <rel> has changed since <label>.`
    3. Write `before/` back, deleting files the entry added. Delete the entry's created directories (recursive, if they exist). Update `files/` and `_known`.
    4. Restore the state and registry (Task 3).
    5. Move the entry to redo and return the message.
  - **`Redo()`:** the mirror. Check against `before/`, write `after/`, and recreate a created directory only as its files need it.
  - **Message:** `restored` counts paths whose target version exists and `removed` counts those whose target is missing. With exactly one path, name it (`restored Shop\Book.cs` / `removed Shop\Book.cs`). Use `Path.DirectorySeparatorChar` in the relative paths.
  - **`Dispose`:** delete the shadow folder, and swallow IO errors.
